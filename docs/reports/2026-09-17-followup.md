# Follow-up report, 2026-09-17

The report review, the linker decision, the chapter re-cut and the standard library are in `main`. On the development Mac, macOS arm64, the build has zero warnings. All 639 ctest tests pass, and so do ASan and UBSan builds. No test is skipped since the owner fetched the Windows sysroots. `docs/decisions.md` holds each decision below in full.

## Decisions changed

- **Doc warnings:** antic warns about a `//#` note without `///` only under `--doc-warnings`, which `anti check` passes. The "in every compilation" line is gone.
- **Parameter names:** library format version 10 keeps them, and the header prints them. `antl_scale` compares the bytes of a file with a parameter name.
- **Zero-width bitfields:** `_: T : 0` stays as a unit break under System V, AAPCS64 and MSVC, as clang lays it out. The ABI probe holds the struct `Breaks`.
- **LLVM pin:** `tools/check-llvm.cmake` checks llvm-mc, llvm-ar, `ld.lld`, `ld64.lld` and `lld-link` against `tools/llvm-version`. The workflow runs it after every install. The build copies the checked tools into `bin/` of the runtime archive. Chapter 3 names `llvm@23`.
- **c_wchar:** `program_abi_wchar` converts 0x80000001 to `i64`. clang on macOS gives -2147483647, and antic gave 2147483649. `c_wchar` now takes the signedness of `wchar_t` on each target.
- **Linker:** lld links every target, and `--linker platform` selects the fallback. The runtime archive holds `sysroot/<target>` and `licenses/`. `cross_link_<target>` checks format and architecture with llvm-objdump. Chapters 3, 16, 21 and 23 and the driver follow it.
- **Name:** chapter 1 has the recursive acronym once, recorded beside the naming decision.

## Provisional decisions

### Bitfields and header

- A zero-width bitfield is spelled `_: T : 0`. The grammar already reads `_` as a field name.
- A union holds no zero-width bitfield. C compilers disagree on its effect there.
- A header name that C11, C++17 or a standard macro takes gets a trailing `_`. The header compiles as C and C++.

### Linker and sysroots

- The Linux sysroot is musl 1.2.6 and compiler-rt 22.1.3 from Alpine 3.24, pinned by SHA-256. The packages ship `libc.a` and the builtins that `printf` needs on ARM64.
- A Linux executable is a static PIE against musl. It runs without a C library on the system.
- macOS takes the stubs of MacOSX26.5.sdk. ld64.lld 23.1.1 refuses the stubs of 27.0.
- Mach-O bundles join with Apple's `ld -r`. ld64.lld does not implement `-r`.
- antic runs lld from `bin/` of the runtime archive, or from the search path. Without a Windows sysroot, lld-link reads `LIB`.
- `tools/get-sysroot.sh` runs xwin only with `--accept-license`. Only the owner of the build can accept the Microsoft terms.
- clang compiles the runtime for every target with a sysroot. A link for a target needs its runtime.
- Homebrew installs `llvm@23` and `lld@23`, and the check runs each lld name. Homebrew ships lld as its own formula.

### Standard library

- The build writes `anti.io`, `anti.text` and `anti.license` into `std/` of the runtime archive, and antic searches it after `-I`. A program imports them without a manifest.
- `anti.text` counts `byte_count` and `char_count`, and `anti.io` has `print`, `println`, `eprint`, `eprintln` and `exit`. A `str` holds valid UTF-8.
- The modules call C functions in `rt/io.c`, `rt/text.c` and `rt/license.c`. Anti builds no `str` from a pointer and a length.
- A bundled runtime leaves out `rt/license.c`, which needs `anti_licenses`.

### Book and tests

- `tests/excerpts.txt` lists every C and CMake fence that a repository file holds, and `excerpt_<chapter>_<number>` checks each. `tools/scripts/excerpts.py` writes the list.
- Fences that quote an earlier chapter commit stay out: code of chapters 1, 3, 4 and 5 and seven of chapter 12.
- The re-cut chapters 13, 14 and 15 are three new commits on top of `main`. Rebuilding the old commits needs a force push of `main`, from which the site takes the book.
